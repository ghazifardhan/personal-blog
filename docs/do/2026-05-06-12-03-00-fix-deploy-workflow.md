# Task Documentation: Fix GitHub Actions Deploy Workflow

## 1. Task Overview
The user reported that the GitHub Actions deploy workflow (`deploy.yml`) was failing on the SSH step with multiple errors: `Permission denied (publickey)` for Git, `yarn: command not found`, and `Unit personal-blog.service not found`. The workflow was attempting to pull the code and build the Nuxt 3 project directly on the VPS, which was lacking the proper environment configuration. 

## 2. Changes Made
* **Modified**: `.github/workflows/deploy.yml`
  * Removed the bash commands in the SSH step that attempted to run `git pull`, `yarn install`, and `yarn build:prod` on the VPS.
  * Added a new step using `appleboy/scp-action@master` to copy the `.output` build directory (generated by the GitHub Actions runner) directly to the target directory on the VPS.
  * Preserved the SSH step to only run `sudo systemctl restart personal-blog` to restart the application after the fresh build is deployed.

## 3. Technical Decisions
Instead of trying to configure Git SSH keys and install Node/Yarn natively on the VPS to support server-side building, the decision was made to build the application on the GitHub Actions runner and copy the compiled output (`.output` directory). This is a best practice for CI/CD because:
- It eliminates the need for build tools on the production server, minimizing the server footprint and potential security risks.
- It leverages the ephemeral GitHub Actions runner environment, which reliably provisions Node.js and dependencies for every run.
- It ensures that only the production-ready artifacts are deployed, avoiding deployment of source code or dev dependencies.

## 4. Verification
- Validated that the `deploy.yml` now utilizes `scp-action` pointing to `.output` as the `source`, mapping correctly to the remote path.
- The `ssh-action` step is retained solely for bouncing the systemd service.
- *Note:* The user must ensure that `personal-blog.service` is correctly installed on the VPS (e.g., copied to `/etc/systemd/system/personal-blog.service` and enabled) for the final restart command to succeed.
