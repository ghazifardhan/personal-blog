# Task Overview: Switch CI/CD to Yarn

Switched the package manager in the GitHub Actions workflow from `pnpm` to `yarn` to resolve native module binding errors (`better-sqlite3`).

## Changes Made

- **Modified**: `.github/workflows/deploy.yml`
  - Replaced all `pnpm` commands with `yarn` commands.
  - Removed `corepack enable` as `yarn` is available by default on the runner and matches the existing `yarn.lock`.

## Technical Decisions

- **Lockfile Consistency**: Since the project contains a `yarn.lock` but no `pnpm-lock.yaml`, using `yarn` ensures that the dependencies are installed exactly as expected, which resolves the native binding issues with `better-sqlite3`.
- **Simplification**: Removed manual `corepack` setup to simplify the workflow.

## Verification

- The user can verify by pushing the change and checking the GitHub Actions log. `yarn` is much more likely to handle the `better-sqlite3` build correctly given the existing lockfile.
